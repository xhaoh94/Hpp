# Hpp v0.1.3 发布说明

> 发布日期：2026-10-10
> 包含：Windows / Android / Linux（Linux 由 GitHub Actions 构建）

## 本次版本主要改动

### 🤖 子 Agent 稳定性（核心修复）
- **修复子 Agent 频繁失败却显示「未返回输出」且不报错**：Pi 在 `json`/`rpc` 模式下上游报错（overloaded / rate limit / 5xx）仍返回退出码 0，旧逻辑只按 `exitCode` 判定成败，导致真实的 `errorMessage` 被静默吞掉。现在改为以 `stopReason`（error/aborted）与 `errorMessage` 为准，失败原因真实透出，UI 正确提示。
- **新增上游错误自动重试 + 抖动退避**：识别可重试的上游错误（overloaded / rate limit / 429 / 5xx / 连接层）后最多重试 2 次，间隔 15s / 45s 并叠加随机抖动（避免并行子进程同步捶打上游）；中断与超时不再重试。
- **并行汇总预算修正**：工具结果整体按 32KB 均分到各任务（此前误用单任务 8KB 预算，任务一多后续整段静默丢失）。

### ⚙️ Agent MCP / codemode 配置
- **默认 exposure 修正为 `codemode`**（此前误为 `direct`，导致工具未按预期暴露）。
- **新增 codemode 配置弹窗**与 **MCP 配置弹窗**：作用域内校验、别名归一（`codemode-deferred` 等），文案与真实默认档一致。
- **路径归一化对齐 Pi 的 `normalizePath`**（展开 `~` / Git-Bash·MSYS·Cygwin·WSL 盘符 / `file://`），修复「配置写在 A、Pi 读 B」的静默错位；主进程与 worker 两侧实现双登记。
- **`writeMcpConfig` 改为读-改-写**，保留其他顶层键（如 `autoEnableCodemode`），不再静默删除；遇到非法 JSON 时拒绝写入并指明路径。

### 🔌 Pi SDK 适配
- 跟进 Pi SDK 升级到 1.0/1.1：协议解析、用量上报、渠道选择复用 SubAgent 的 `providerModelOptions`，压缩模型可直接从已配置渠道选择。

### 💬 会话与交互
- 新增上下文显示（会话上下文内容可视化）。
- 优化编辑渠道：新增切换模型提示，修复渠道弹窗新增/修改模型后立即切换报 `Model switch failed: Pi model is not available`（worker 模型注册表改为切换前重新读取磁盘配置）。
- 审核撤销功能持续打磨（含 Windows CRLF 行尾补丁字节级精确还原）。

### 🖥️ 桌面与插件稳定性
- 插件进程生命周期与注册表加载稳定性优化。
- 远程桥接与数据持久化优化，提升移动端连接桌面端的同步可靠性。
- 修复 subagent 超时时间过短导致任务被提前中断。
- 新增 worker 侧 `.mjs` 的打包登记规则（vite workers 数组 + verify-pi-package 必检清单），避免漏登记导致运行时 module-not-found。

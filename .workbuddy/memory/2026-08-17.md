## 编辑区与聊天区滚动条改为 overlay（hover 显示）

需求：编辑区和聊天区域滚动条，鼠标不在对应区域时不显示。

现有 `global.css` 已有 `.overlay-scroll` 工具类（thumb 默认透明，`:hover` 显示），但两个主滚动容器未使用。直接在容器 CSS 写 overlay 样式（不改 TSX）：

1. **编辑区** `EditorArea.css` — `.editor-pane-codemirror .cm-scroller`
2. **聊天区** `ChatPanel.css` — `.chat-messages`

两处统一：
- `scrollbar-width: thin` + `scrollbar-gutter: stable` + `scrollbar-color: transparent transparent`
- `:hover` 时 `scrollbar-color: var(--scrollbar-thumb) transparent`
- webkit：`width/height: 8px`、track transparent、thumb 默认 transparent、`:hover` 显示 `var(--scrollbar-thumb)`、thumb `:hover` 显示 `var(--scrollbar-thumb-hover)`
- 与现有 `.overlay-scroll` 行为一致，避免内容因滚动条显隐而抖动

## 编辑区 Lua/C# 升级为 VSCode 同款 TextMate 语法高亮

需求：legacy StreamLanguage 高亮与 VSCode 差距太大，引入 VSCode 同款引擎（vscode-textmate + oniguruma）。

**技术要点**：
- npm 上不存在 Lua/C# 的 CodeMirror 6 Lezer 解析器（@lezer/lua、@codemirror/lang-csharp 均 404），TextMate 是唯一能达到 VSCode 级效果的路线
- 依赖：`vscode-textmate@9.3.2` + `vscode-oniguruma@2.0.1`
- 语法文件：C# 用 dotnet/csharp-tmLanguage 仓库 `grammars/csharp.tmLanguage`（**plist 格式**，vscode-textmate 按文件后缀自动选 plist/JSON 解析）；Lua 用 VSCode 内置 `extensions/lua/syntaxes/lua.tmLanguage.json`
- Lua grammar 引用了 `source.c`（FFI 内嵌 C），需在 loadGrammar 里注册最小 C grammar 兜底

**文件结构**（src/components/editor/）：
- `tm-highlight-worker.ts` — Web Worker：初始化 oniguruma wasm + grammar registry，`grammar.tokenizeLine` 逐行全量 tokenize（状态机跨行），scope→class 映射后返回 `TmWorkerLine[]`
- `tm-highlight.ts` — 主线程桥接：worker 单例 + ViewPlugin（150ms 防抖、文档变化重排、tokenize 期间再次变更自动重跑）+ StateEffect（EditorPane 加载完成后通知启用）+ buildTmDecorations（字符级 mark decoration `cm-tm-<cls>`）
- `onig-wasm-base64.ts` — **自动生成**（node 脚本）：onig.wasm → base64 常量（630KB）。不能用 vite `?url`（生产 file:// 下 fetch 被 Chromium 拦截）也不能用 `?inline`（vite 对 .wasm 特殊处理会解析失败），base64 常量最稳
- `grammars/csharp.tmLanguage.plist` + `grammars/lua.tmLanguage.json` — 用 `?raw` 导入打包进 worker bundle

**集成**（EditorPane.tsx）：
- 新增 `langCompartment` 包裹 getLanguageExtension；启用 TextMate 时 `reconfigure([])` 移除 StreamLanguage，避免 tag 着色覆盖 decoration
- readFile 成功后 dispatch `tmEnableEffect`：lua/cs 且 ≤500KB 且 ≤20000 行才启用，否则回退 StreamLanguage
- 颜色在 EditorArea.css 追加 `.cm-tm-*`（Dark+）+ `:root[data-theme="light"]` 覆盖（Light+）

**scope→class 映射**（顺序敏感）：comment/string/number/constant/keyword/type/function/variable/parameter/property/label/preprocessor/operator/punctuation/link/strong/emphasis/heading；`keyword.operator` 必须在 `keyword` 前，`variable.parameter` 在 `variable` 前

**坑**：
- `Compartment.of()` 直接接受 Extension 数组，不要 spread（否则 TS2556）
- Git Bash heredoc `cat >>` 追加文件会 Permission denied，用 Edit 工具
- 构建验证：out/ 目录被运行中进程锁定，safe-delete 超时 → 用临时 vite 配置构建到独立目录验证 worker 打包

## 修复 TextMate 高亮不生效（用户反馈"跟之前没区别"）

**根因**：`tm-highlight.ts` 中 worker 响应处理 `entry.resolve(msg)` 把整个 `{id, ok, tokens}` 对象 resolve 出去，而调用方 `runTokenize` 期望 `TmWorkerLine[]`。`buildTmDecorations` 里 `tokens.length` 为 undefined → `Math.min` 得 NaN → 循环不执行 → decoration 恒为空。引擎实际在跑，但一个 token 都没画。

**修复**：
- `resolve(msg.tokens ?? [])`（核心）
- worker 失败时从"静默变白板"改为恢复原 StreamLanguage：`TmHighlightPluginOptions` 新增 `fallbackLanguage: Extension[] | null`，catch 中 `langCompartment.reconfigure(fallbackLanguage)`；EditorPane 传 `getLanguageExtension(path)` 结果
- `vscode-textmate`/`vscode-oniguruma` 补进 package.json dependencies（之前只在 node_modules，重装会丢）

**排查方法（可复用）**：写 `scripts/verify-tm.cjs` 在 Node 里直接 loadWASM(本地 onig.wasm) + registry + parseRawGrammar(项目内 grammar 文件) + tokenizeLine 验证引擎链路，Node 通过后问题锁定在浏览器/worker 侧。已排除：index.html 无 CSP、dev server 模块 200、HMR 已推送。

**遗留**：HMR 只更新组件代码，已打开的编辑器实例（useEffect 依赖 path 不变）不会重建 → 用户需关闭重开 lua/cs 标签或重启 dev 才能看到新高亮。

## TextMate 仍不生效（第二轮排查，用户再报"一模一样"）

**全链路静态验证（全部通过）**：
1. dev server 正常——**排查教训：curl 请求 dev server 时 URL 不要带 `/src/` 前缀**（electron-vite renderer root 是 src/，模块 URL 是 `/components/editor/...`），带前缀会被 SPA 回退成 index.html，之前误判"模块 200"其实都是回退页
2. worker 转换正常：`vscode-oniguruma`/`vscode-textmate` 走 optimizeDeps 预构建，`?raw` grammar → `?import&raw` 正常返回字符串（plist 289KB / json 22KB）
3. `onig-wasm-base64.ts` 的 base64 与磁盘 onig.wasm **逐字节一致**（473151 字节，魔数 0x00 0x61 0x73 0x6d）
4. grammar 请求响应正常（Content-Length 正确）
5. Node 里 verify-tm.cjs 引擎 tokenize 正常

**结论**：代码链路是通的，问题在运行时（worker 失败或 HMR 后编辑器实例未重建）。因无法看到浏览器运行时状态，加了三层诊断：
- **状态栏 TextMate 徽标**（EditorArea.tsx 新增 `TmStatusBadge` + `tmStatusMap`）：`TextMate ✓` / `TextMate ✗ (原因)`，EditorPane 通过 `onTmStatus` prop 上报（tm-highlight.ts 新增 `TmStatus` 类型 + options.onStatus 回调）
- **console 日志**：EditorPane readFile 后打印 `[TextMate] path -> lang/bytes/lines/enabled`；worker 打印 wasm 初始化、tokenize 行数/token 数；失败时 console.error 具体原因
- worker 失败回退时仍保留 fallbackLanguage

**验证脚本**：`scripts/verify-tm.cjs`（引擎链路）+ 临时 `scripts/verify-wasm-base64.cjs`（base64 解码对比，已删除，验证完即弃）。

## TextMate 状态栏徽标排查（用户报"还是灰色 TextMate –"）

**现象**：用户刷新页面后能看到状态栏灰色 `TextMate –`（说明组件层新代码已生效），但打开 `.cs`/`.lua` 后徽标不变绿。

**排查结论**：代码链路完整（constructor 上报 idle → EditorPane dispatch tmEnableEffect → 插件 update() 收到 effect → onStatus({kind:"on"}) → EditorArea setTmStatusMap → 徽标变绿）。用户看到 `–` 有两种来源且 UI 相同：`tmStatusMap[key]` 为 undefined（onStatus 从未被调用）或上报了 idle。**根因锁定为 HMR 半新半旧**：HMR 更新了 React 组件层（能看到徽标），但已创建的 CodeMirror EditorView 实例不会重建，旧插件类没有 onStatus 上报逻辑，且旧类的 `effect.is(tmEnableEffect)` 用的是旧常量，新 dispatch 的 effect 匹配不上 → 永不回调。

**措施**：
- EditorArea 状态栏新增版本标记 `TM v3`（判断页面新旧的决定性标识）
- EditorPane 新增 `lastTmStatusRef` 记录插件最后上报状态 + 防御检测：dispatch tmEnableEffect 后 2 秒内若插件未上报非 idle 状态，console.warn 明确提示"编辑器实例疑似旧代码（HMR 不重建 EditorView），请重启 dev"
- **用户操作**：彻底关闭应用窗口 → Ctrl+C 停 npm run dev → 重新 `npm run dev`（Ctrl+R 在 Electron 下可能被拦截且 HMR 状态半新半旧，不可靠）

**教训**：开发期改 CodeMirror 插件/EditorView 扩展代码后，必须完整重启 dev 才能生效；刷新页面或 HMR 都不可靠。判断"页面是否最新"用 TM v3 徽标一眼可辨。

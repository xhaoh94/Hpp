## 给项目加 Dev 自动化调试设施（解决"每次改代码都要用户重启反馈"的效率问题）

背景：TextMate 高亮一直显示灰色 idle，用户每次都要手动重启 dev + 反馈，效率极低。本次一次性配置自动化调试能力。

### 改动
1. `electron/main.ts`
   - dev 模式启用 `app.commandLine.appendSwitch("remote-debugging-port", "9222")`（CDP 端口，须在 app ready 前）
   - `webContents.on("console-message")` 把渲染进程所有 console 输出落盘到 `.workbuddy/renderer-console.log` 并同步打印到 dev 终端
   - dev 模式禁用硬件加速 `app.disableHardwareAcceleration()`，避免无 GPU/沙箱环境启动崩溃
2. `src/components/editor/tm-highlight.ts`
   - 新增 `tmDebug` 全局调试对象（version/pluginCreated/lastStatus/statusCounts/tokenizeCount/tokenizeErrorCount/lastTokenizeLines/lastDecoCount/lastError），挂到 `window.__tmDebug`，CDP 可直接读取
   - 插件内所有状态上报统一走 `reportStatus()` 更新 tmDebug
3. 新建 `scripts/tm-debug.cjs` —— CDP 诊断脚本：
   - 默认：读取状态栏徽标、当前打开文件、`window.__tmDebug`、`.cm-tm-*` decoration 数量
   - `--screenshot`：Page.captureScreenshot 截图到 `.workbuddy/debug-screenshot.png`
   - `--log [N]`：读 renderer-console.log 尾部
   - `--eval <js>`：页面执行任意 JS

### 用法（以后诊断不再需要用户反馈）
```bash
node scripts/tm-debug.cjs            # 看运行时状态
node scripts/tm-debug.cjs --log 100  # 看渲染进程日志
node scripts/tm-debug.cjs --screenshot  # 截图看 UI
```

### 坑
- electron-vite dev 下主进程改代码需要重启 dev 才生效（CDP 端口、console 落盘都在主进程）
- `console-message` 事件在 Electron 43 用新版事件对象签名 `(event) => event.message/event.level/event.lineNumber/event.sourceId`
- Bash 工具环境默认带 `ELECTRON_RUN_AS_NODE=1`，我启动 dev 时会崩；用户终端正常
- Windows 沙箱内启动 Electron 会触发 GPU 进程崩溃，需 `dangerouslyDisableSandbox` 或加 `--disable-gpu`

## 修复 TextMate 高亮插件崩溃（C# 显示灰标的真正原因）

背景：用户反馈 C#（`docs/LuaHelper.cs`）状态栏始终灰色 `TextMate –`，高亮与旧版无区别。

### 根因
`src/components/editor/tm-highlight.ts` 的 `update()` 回调内直接调用 `this.view.dispatch(...)` 清空语言 Compartment：

```ts
this.view.dispatch({ effects: options.langCompartment.reconfigure([]) });
```

CodeMirror 6 禁止在 update 生命周期中再次 dispatch，抛出：

```
Error: Calls to EditorView.update are not allowed while an update is in progress
```

插件一收到启用指令即崩溃，徽标永远 `idle`，tokenize 从未执行。

### 修复
将该 dispatch 推迟到当前 update 完成后：

```ts
queueMicrotask(() => {
  if (!this.disposed) {
    this.view.dispatch({ effects: options.langCompartment.reconfigure([]) });
  }
});
```

### 验证结果（通过 CDP + 截图）
- `window.__tmDebug.lastStatus.kind === "on"`
- `tokenizeCount = 1`，`lastTokenizeLines = 1623`，`lastDecoCount = 8743`
- 截图可见 `using`/`class`/`static` 蓝色、命名空间/类名青色、状态栏 `TextMate ✓`
- C# 配色与 VSCode Dark+ 一致

### 遗留
- ~~dev 模式开启 CDP 9222 + renderer console 落盘 + disableHardwareAcceleration~~（已清理）
- 生产构建不包含这些调试设施（`is.dev` 判断）

## 清理根目录 electron-vite 配置缓存文件

用户发现根目录有 4 个相同文件 `electron.vite.config.<毫秒时间戳>.mjs`（10:28–10:31 生成，内容 MD5 一致）。

### 原因
electron-vite 每次 dev 启动会用 esbuild 把 `electron.vite.config.ts` 打包成临时 `.mjs` 缓存（文件名带毫秒时间戳），正常退出自删；今天调试期间多次 taskkill 强杀 dev 进程，清理未执行导致遗留。

### 处理
- 删除 4 个 `electron.vite.config.*.mjs`
- 删除 `scripts/verify-tm.cjs`（临时验证脚本，注释自述"验证通过后可删除"）
- 删除 `.workbuddy/debug-screenshot.png`（CDP 截图遗留）
- `.gitignore` 新增 `electron.vite.config.*.mjs` 防止复发

### 遗留（未删，需用户确认）
- `docs/LuaHelper.cs`、`docs/ServerSelectDataModel.lua`：调试时用的测试样例文件，位于 docs/，是否保留由用户决定

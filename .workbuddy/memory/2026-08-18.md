背景：TextMate 高亮一直显示灰色 idle，用户每次都要手动重启 dev + 反馈，效率极低。本次一次性配置自动化调试能力。

   - 插件内所有状态上报统一走 `reportStatus()` 更新 tmDebug
3. 新建 `scripts/tm-debug.cjs` —— CDP 诊断脚本：
   - 默认：读取状态栏徽标、当前打开文件、`window.__tmDebug`、`.cm-tm-*` decoration 数量
   - `--screenshot`：Page.captureScreenshot 截图到 `.workbuddy/debug-screenshot.png`
   - `--log [N]`：读 renderer-console.log 尾部
   - `--eval <js>`：页面执行任意 JS


## 修复 TextMate 高亮插件崩溃（C# 显示灰标的真正原因）

背景：用户反馈 C#（`docs/LuaHelper.cs`）状态栏始终灰色 `TextMate –`，高亮与旧版无区别。

### 根因
`src/components/editor/tm-highlight.ts` 的 `update()` 回调内直接调用 `this.view.dispatch(...)` 清空语言 Compartment：

```ts
this.view.dispatch({ effects: options.langCompartment.reconfigure([]) });
```

CodeMirror 6 禁止在 update 生命周期中再次 dispatch，抛出：

```
Error: Calls to EditorView.update are not allowed while an update is in progress
```

插件一收到启用指令即崩溃，徽标永远 `idle`，tokenize 从未执行。

### 修复
将该 dispatch 推迟到当前 update 完成后：

```ts
queueMicrotask(() => {
  if (!this.disposed) {
    this.view.dispatch({ effects: options.langCompartment.reconfigure([]) });
  }
});
```

### 验证结果（通过 CDP + 截图）
- `window.__tmDebug.lastStatus.kind === "on"`
- `tokenizeCount = 1`，`lastTokenizeLines = 1623`，`lastDecoCount = 8743`
- 截图可见 `using`/`class`/`static` 蓝色、命名空间/类名青色、状态栏 `TextMate ✓`
- C# 配色与 VSCode Dark+ 一致

### 遗留
- ~~dev 模式开启 CDP 9222 + renderer console 落盘 + disableHardwareAcceleration~~（已清理）
- 生产构建不包含这些调试设施（`is.dev` 判断）

## 编辑区 minimap：收窄宽度 + 选中文本在缩略图标注相同文本

需求：① minimap 宽度缩小一点；② 选中文本时，把文档里"相同的文本"在 minimap 预览里标注出来。

**根因/约束**：`@replit/codemirror-minimap` 宽度硬编码 120px（`Scale.MaxWidth`），无公开 width 配置；且不暴露任何 API 在 canvas 上标注任意文本（只内置 selection / diagnostics 两种绘制）。直接改 node_modules 会在重装时丢失。

**方案：把包 vendor 进项目再扩展**（比改 node_modules 更稳、可进版本库）：
- 新增 `src/lib/codemirror-minimap/index.js` + `index.d.ts`（从 `node_modules/@replit/codemirror-minimap/dist/` 拷出，1182 行）。
- 在 vendored 模块里：
  1. `Options` 加 `width?: number`；`Config.combine` 默认值加 `width: undefined`；`getWidth()` 优先用 `facet(Config).width`，否则走原 120px 缩放逻辑。
  2. 新增 `MatchesState`（继承 `LineBasedState`）：在 `update()` 中，当 `selectionSet/docChanged/foldsChanged` 时，取 `selection.main`，用 `doc.indexOf` 扫出文档内所有相同文本出现的**行号**（跳过空白、>200 字符、或 >300k 的超大文档，最多 5000 处）。`drawLine()` 在每个命中行画：整行淡蓝底（alpha 0.18）+ 左侧 3px 蓝色强调条（`MATCH_COLOR = "#3b82f6"`，深浅主题都清晰）。
  3. `minimapClass` 构造加 `this.matches = matches(view)`；`update()` 调 `this.matches.update(update)`；`render()` 主循环 `this.matches.drawLine(...)` 放在 text/selection/diagnostic 之前（作为背景）。
- `src/components/editor/EditorPane.tsx`：`showMinimap.of({...})` 加 `width: 80`（原 120 → 80，肉眼"小一圈"）；import 从 `@replit/codemirror-minimap` 改为本地 vendored 路径 `../../lib/codemirror-minimap/index.js`。
- `src/components/editor/EditorArea.css`：`.editor-find-widget` `right: 140px → 100px`、`max-width: calc(100% - 160px) → calc(100% - 120px)`，避让更窄的 minimap。

**验证**：`tsc -p tsconfig.web.json --noEmit` 对本项目文件无报错（仅 preexisting 的 test 文件 node 类型错误，与本改动无关）；`vitest run src/components/editor` 34 passed / 1 failed（失败的 `EditorWiring.source.test.ts` 断言 `electron.vite.config.ts` 含 `hmr: false`，属 preexisting、未动该文件）。vendored 模块被 `EditorPane.source.test` 成功 import 说明无语法/解析错误。
诚实限制：Electron 桌面应用，沙箱无法渲染窗口，实际 minimap 视觉与选中高亮需用户在编辑器实机确认。

## 查找控件三 bug 修复：面板位置乱跳 / 自动打开首个匹配文件 / 切文件重复搜索

### Bug 1：面板位置乱跳
- **根因**：`EditorArea.tsx` 的 `useLayoutEffect` 用 `document.querySelector(".editor-find-widget")` 选取搜索栏来定位面板，但多 tab 场景下隐藏 pane 的 widget（`display:none`）的 `getBoundingClientRect()` 返回全零，`panelTop` 算出 `0 - areaTop + 8`，面板跳到顶部。
- **修复**：querySelector 改为 `.editor-pane:not(.editor-pane-hidden) .editor-find-widget`（只取可见 pane 的 widget）；`useLayoutEffect` deps 加 `activeKey`，切 tab 时重新测量并重新 observe 新 widget。

### Bug 2：切文件时老是打开第一个匹配文件
- **根因**：`EditorPane.tsx` 的 `visible` effect 在 pane 可见时设 `pendingScrollRef.current = 0` + `setNavTick++`。scope==="all" 时 `displayMatches[0]` 是项目级第一个匹配，可能属于其他文件 → scroll effect 调 `requestGotoMatch(path, line)` → 打开该文件 → 又触发 visible effect → 循环。
- **修复**：`visible` effect 中加条件 `sharedSearchConfig.searchScope !== "all"`，scope 为 "all" 时不做自动滚动到首个匹配。

### Bug 3：输入不变切文件时重复搜索
- **根因**：新 pane 挂载时 debounce effect 首次运行（mount 时所有 effect 执行），即使 query/options 未变也触发 `onRunAllFilesSearch(false)` 重新遍历项目文件。explicit 选择"所有文件"后 debounce 250ms 后也会重复一次搜索。
- **修复**：`searchConfig.ts` 新增 `lastAllFilesSearchKey` 字段（JSON 串）；`EditorArea.tsx` 的 `runAllFilesSearch` 在发起搜索前同步写入 `sharedSearchConfig.lastAllFilesSearchKey`；`EditorPane.tsx` 的 debounce effect 先构建当前参数键，与 `lastAllFilesSearchKey` 比对，相同则 `return` 跳过。

- `vitest run src/components/editor/EditorPane.source.test.ts`：全通过。

## 查找控件四修：输入抢焦点/跨文件自动跳 / 无匹配不弹 / 关窗后重搜新内容重开

### 问题 1：输入框编辑文本导致刷新中断焦点 + 自动跳到第一个匹配
- **根因（共同）**：`EditorPane.tsx` 搜索框 `onChange` 在 scope==="all" 时仍 `pendingScrollRef=0 + setNavTick++` → 滚动 effect 取 `displayMatches[0]`（可能是其他文件的匹配）→ `requestGotoMatch` 打开那个文件 → 当前 pane 变 `editor-pane-hidden`（切走页签）→ 输入框失去焦点、且"跳到第一个匹配文件"。
- **修复**：
  - `onChange` 改为仅 `searchScope==="current"` 时才 `pendingScrollRef=0 + setNavTick++`；scope==="all" 只 `setSearchQuery`（刷新计数/高亮，不滚动、不跨文件跳转）。
  - 滚动 effect 的 cross-file 分支加 `crossFileNavAllowedRef` 守卫：仅 `navigateSearch`（↑/↓）显式置 `true` 时才 `requestGotoMatch` 跨文件打开；打开搜索/输入文本等隐式动作不自动打开其它文件。
  - 结果：scope=all 打字不再切页签、不抢焦点；当前文件范围行为不变。↑/↓ 仍可跨文件跳转（显式导航）。

### 问题 2：匹配不上不需要显示弹窗
- **根因**：`runAllFilesSearch(openPanel=false)`（输入检索）沿用 `open: state.open`，若面板原本开着、检索后无结果，面板仍开着显示"未找到"空态。
- **修复**：无匹配分支统一 `open: false`（始终不显示面板/空态）；仅显式 `openPanel=true`（下拉选"所有文件"/重开按钮）无匹配时给 toast 提示。

### 问题 3：关闭弹窗后，重新搜索了新内容要重新弹窗
- **根因**：上一轮逻辑是关窗后无论是否新内容都保持关闭（重开按钮常驻）。
- **修复**：`expandSearch` state 新增 `dismissedQuery`（手动关窗时的搜索词，×/Esc 三处关闭路径均写入 `state.query`）。`runAllFilesSearch` 命中时：
  - `openPanel=true` → 打开；
  - 否则 `state.open`（已开则保持）→ 否则 `query !== state.dismissedQuery`（关窗后搜的是新内容）→ 重开；否则保持关闭（重开按钮仍显示）。
  - 重开按钮点击、`onSearchScopeChange` 切回"当前文件"都清空 `dismissedQuery`。
- **新行为**：关窗后切 tab（参数不变，debounce 去重跳过）仍保持关闭+按钮；关窗后输入新内容并命中 → 自动重开；关窗后无匹配 → 仍关闭。

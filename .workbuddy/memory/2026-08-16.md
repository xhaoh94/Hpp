## 修复代码审查弹窗跳转定位 bug

### 问题
1. 打开弹窗偶现不跳转到第一个修改处
2. 点击"下一个"偶现跳转位置不准确

### 根因
1. `scrolledRef` 在弹窗关闭后未重置，再次打开同一文件时被跳过
2. `scrolledRef.current = key` 在 `diffPairIndices.length === 0` 检查之前设置，diff 列表暂时为空时永久跳过
3. 文件内容异步加载后 `pairs` 从 `linesToPairs` 变为 `buildFullFileDiff`，`diffPairIndices` 变了但始终滚到 0 而非当前游标位置
4. `scrollToDiff` 闭包捕获的 `diffPairIndices` 在 rAF 回调执行时可能已过期

### 修复（CodeReviewDialog.tsx）
- 将 `scrolledRef` 和新增的 `diffPairIndicesRef` 移到组件顶部 ref 区
- 弹窗打开时重置 `scrolledRef.current = null`
- 自动定位 effect：先检查 `diffPairIndices.length` 再设 `scrolledRef`，用 `Math.min(diffCursor, ...)` 代替固定的 0
- `scrollToDiff` 改为读取 `diffPairIndicesRef.current`，避免闭包过期
- effect 依赖数组加入 `diffCursor`

## 修复文件预览打开大文件后卡顿问题

### 问题
打开大压缩包后关闭，再打开正常文件会卡顿很久

### 根因
1. 二进制检测之前：`readFile(filePath, "utf-8")` 把整个大压缩包读为 UTF-8 文本，产生巨大字符串
2. 巨大字符串通过 IPC 传到渲染进程，存入 React state，触发 `content.split("\n")`、`buildHighlightedLines`、`findTextMatches` 等昂贵 memo
3. 关闭后旧的大字符串和派生对象等 GC 回收，导致卡顿
4. 缺少文件大小限制，超大文本文件同样会全量读入

### 修复（file-handlers.ts）
- 新增 `MAX_TEXT_FILE_BYTES = 10MB` 限制
- 大文件（>10MB）：只做 8KB 二进制探测，是二进制则返回 `binary: true`，是文本则返回"文件过大"错误
- 小文件（≤10MB）：全量读为 Buffer，检查二进制后返回 UTF-8 内容
- 移除动态 `import("fs/promises")`，改为静态 import `open`
- 同时修复了 `readFile` 未检查 `isFile()` 的问题

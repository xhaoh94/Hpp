### 问题：虚拟化已存在但仍滚动卡（侧边栏/聊天区/切文件跟着卡）
- 定位：虚拟化数学本就正确（二分只渲染可视窗口几十行），并非"没用虚拟列表"。真正拖慢两根因：
  1. `onScroll` 未节流——滚动事件每帧多次触发，每次同步 `setScrollTop` → React 重渲染，主线程被反复占用，抢占整个 app 事件循环（侧边栏/聊天区响应随之变慢）。
  2. 行组件未 `memo`——滚动时整批可见行每帧重新协调，即使内容/位置（固定 row.offset）未变。
- 修复：
  - `onScroll` 改 `requestAnimationFrame` 节流（`latestScrollTop` ref + `rafRef`），每帧最多一次 `setScrollTop`；卸载时 `cancelAnimationFrame`。
  - 每行抽成 `React.memo` 的 `ExpandSearchRow`：滚动时 props（`row` 引用来自稳定 memo、`replaceOpen/Query/preserveCase` 值、`onReplace`/`onToggleCollapse` 均为稳定 useCallback）不变 → memo 命中跳过，仅进入/离开视口的行挂载/卸载。
  - 点击跳转逻辑直接放进 memo 行调用稳定 `requestGotoMatch`（移除原先每次新建的 `onPick` 闭包，避免 memo 因 prop 引用变化失效）。
  - `rows` 类型加 `collapsed` 字段，折叠态随行携带，`onToggleCollapse` 稳定回调。
- 验证：`tsc --noEmit` 零错误；`EditorPane.source.test.ts` 34 passed；完整测试 1177 passed / 2 failed（预存 `EditorWiring` HMR + `MarkdownRenderer` padding 断言），无新增回归。

### 问题（修正）：连续拖滚动条经常整片空白、要再拉一下才显示
- 用户复测否认上一轮"overscan=视口 + 保留 rAF"修复有效——连续拖滚动条仍"经常什么都不会渲染出来，再拉一下才可以显示出来"。
- **修正根因**：上一轮把锅甩给"缓冲不足"，但更关键的是 `onScroll` 的 **rAF 节流引入了一帧定位延迟**。行是绝对定位在各自 `row.offset` 上、渲染窗口依赖 `scrollTop` 状态；rAF 让状态落后原生滚动 1 帧，快速连续拖动时**单帧位移超过 overscan 缓冲** → 新视口落在"旧窗口"之外 → 整片空白；放慢/轻推（位移落入缓冲）才显示 = "再拉一下才出来"。这是真正的"延迟渲染"观感来源，纯靠加大缓冲无法根除（极端快速甩动仍会超缓冲）。
- **修复（`EditorArea.tsx`）**：
  - **移除 rAF 节流**，`onScroll` 内**同步** `setScrollTop(event.currentTarget.scrollTop)`（react-window 同款做法）。渲染窗口永远以当前滚动位置为中心、零额外延迟，视口始终被完整覆盖，从根本上消除空白/延迟渲染。React 18 自动批处理使同一帧多次 scroll 事件只触发一次渲染，主线程不会因同步 setState 被反复占用（虚拟化 + memo 行已保证每次仅渲染 ~几十~一百余行）。
  - `overscan` 提到 `Math.max(EXPAND_SEARCH_OVERSCAN_PX, Math.max(viewportH, 0) * 2)`，作为极端快速甩动时偶发单帧渲染延迟的安全缓冲，避免前缘短暂闪白。
  - 删除 `latestScrollTop`/`rafRef`/卸载 cancel rAF 的相关代码。
- 验证：`tsc --noEmit` 零错误；`EditorPane.source.test.ts` 23 passed；完整测试 1177 passed / 2 failed（预存 `EditorWiring` HMR + `MarkdownRenderer` padding 断言），无新增回归。
- 诚实限制：Electron 沙箱无法渲染，拖动流畅度需编辑器实机确认。若仍偶发闪白，可继续上调 overscan 倍率或改 `flushSync`（不推荐，可能告警）。
